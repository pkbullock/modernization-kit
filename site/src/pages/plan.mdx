## Guidance for the PLAN stage of the workflow

After running an assessment and collecting the scope of the page transformation, agree an initial page inventory with site owners, including candidates to retain,
modernise, or retire.

* Agree scope, delivery roles, and a representative pilot with site owners.
* Plan target layouts and mapping requirements for the selected pages.
* Define review criteria, rollout communications, and a recovery approach.

## Site Planning

Before any page transformation can occur, there will need to be target modern sites setup to be the new home for the converted content. Microsoft have a range of resources for [Build an Intelligent Intranet | Microsoft Learn](https://learn.microsoft.com/en-us/sharepoint/intelligent-intranet-overview) and [Plan an intelligent SharePoint intranet](https://learn.microsoft.com/en-us/sharepoint/plan-intranet) that can be a good pre-read into what elements of a SharePoint project to consider.

### Creating new sites

Modern sites cna take a few forms:

- __Microsoft Teams__ - there is an underlying SharePoint site that can be used to store the new content
- __Microsoft 365 Group Teams Sites__ - creating a group will also create an underlying site that can be used to store the page content
- __Modern Sites (Not connected to Microsoft 365 Groups)__ - these are pure SharePoint sites that does not have the additional wrapper functionality around them. These can be connected later if you change your mind.
- __Communication Sites__ typical template for Intranet sites and commonly used for page based content.

When creating these sites, typically classic sites have subsites to help logically group content, the equivelant in modern SharePoint is hub sites and there are quite a few options to consider on how you will structure and map the classic sites to the new locations. Microsoft have a good resource here, that talks about design of hub site structures [Planning your SharePoint hub sites | Microsoft Learn](https://learn.microsoft.com/en-us/sharepoint/planning-hub-sites), if you are considering a multi-site intranet then there is a script sample to create these sites up in bulk.

### Security setup

With modern sites there is a default model for permissions:

- Site Owners - content or site owners will have full control over the site
- Site Members - editors and can see draft content on the site, typicla content owners will have this level of permission
- Site Visitors - read only view of the site, can only see published content on the site.

Consider how the persona's using the site will access the relevant features for their role. Typically, sites can be far more granular in permissions overtime, and context to why permissions were set is not something that can be determined with a script and represents an opportunity to clean up and simply.
